Had an AI Engineer interview. Instead of random tutorials, I:

1. **Took the job requirements**
2. **Mapped them to my skill gaps**

## 🧪 QA Data Science Engineer Bootcamp (3-Day Crash Course)

**For when the role shifts to QA/Data Science Engineer** and testing isn't
your background — a scaffolded, hands-on 3-day bootcamp where you write
the tests yourself against a stub GenAI pipeline:

```
QA-Data-Science-Engineer-Bootcamp/
├── day1_llm_pipeline_testing/         # pytest, pytest-httpx, LangSmith concepts, LLM-as-judge
├── day2_data_contracts_ci/            # Pandera schemas, NumPy/SciPy checks, real GH Actions CI
├── day3_perf_observability_interview/ # Locust load testing, Prometheus/Grafana concepts, mock interview
└── round2_advanced_scenarios/         # advanced follow-up-round prep, written for Qualys specifically
```

Each day ships a working pipeline/service to test against, a TODO-driven
task list (the module doesn't write your tests for you), planted bugs to
catch, and a `solutions/` folder to self-check against once you've
attempted it. `round2_advanced_scenarios/` retells every JD line item as a
chapter in one running, illustrative security-analytics scenario, for
advanced follow-up-round prep. See its [README](./QA-Data-Science-Engineer-Bootcamp/) for the
full roadmap and an explicit reality check on what's learnable hands-on in
3 days vs. what to just talk about fluently.

## 🚀 How to Use This Repo

### Option 1: Job-Description-Driven Learning (Recommended)
1. **Grab a job description** for an AI Engineer role you want
2. **Identify the gaps** between the JD and your current skills
3. **Map those gaps** to the modules here
4. **Build projects** from each module that address those gaps
5. **Write explanations** of your code until you can teach it

### Option 2: Quick Interview Prep
1. **Jump to Module 6** if you need to explain your existing projects
2. **Use Interview-Prep/** for technical questions and STAR method practice
3. **Review CHEAT-SHEET.md** the night before your interview

### Option 3: Fork & Customize
This repo is **open source** for a reason.  
**Fork it. Make it yours. Tailor it for YOUR interview.**

**Traditional learning:**

**This approach:**

2. **Break it down** line by line, explaining every decision
3. **Connect it** to the job description requirements
4. **Practice explaining** until it's muscle memory
